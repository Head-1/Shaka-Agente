# Shaka v0.7.0 — implementação da Etapa B

**Status:** implementada localmente na branch `roadmap/v0.7.0`

## Escopo entregue

A Etapa B implementou o middleware HTTP de correlação, o request ID efetivo e os spans de servidor/operação, além de uma revisão de segurança aprofundada da fachada `Telemetry` e do `Redactor`.

| Área | Entrega |
|---|---|
| Middleware HTTP | `request_context_middleware` no `shaka-api`, aplicado a todas as rotas |
| Request ID | header `x-request-id`; entrada válida preservada, entrada inválida substituída por UUID; resposta sempre devolve o ID efetivo |
| Erros HTTP | corpo JSON e header carregam o mesmo `request_id` |
| Trace context | parsing seguro de `traceparent`, rejeição de IDs zero, versão `ff`, formato inválido e flags inválidas |
| Contexto | `CorrelationContext` inserido em request extensions e propagado por task-local durante o handler |
| Spans | span de servidor com schema/perfil interno, método, rota normalizada, status e classe de status; spans filhos para health, sessão e tarefa |
| Auditoria | eventos de API recebem `correlation_request_id` e `correlation_trace_id`, sem payload ou credencial |
| Contrato | `API_CONTRACTS.md` documenta headers e limites de correlação |
| Changelog | Etapa B e endurecimentos registrados em `CHANGELOG.md` |

## Revisão de segurança do `Redactor`

A revisão encontrou e corrigiu um risco real: uma entrada `Authorization: Bearer abc.def` podia ter o prefixo redacted pela regra genérica e deixar o token após `Bearer` exposto. A expressão agora trata o par completo antes das regras genéricas, com teste explícito.

Também foram corrigidos quatro pontos adicionais:

1. O truncamento agora respeita estritamente o limite configurado, incluindo o sufixo `[TRUNCATED]`.
2. `tenant_ref` é pseudonimizado com SHA-256 truncado e nunca aparece em claro no contexto.
3. Chaves compostas de conteúdo, como `prompt_text`, `model_input`, `response_content` e `tool_result_json`, são redacted por padrão.
4. Falha interna na expressão de redaction degrada para `[REDACTION_FAILED]`, nunca para o texto original.

O redactor continua bloqueando bearer tokens, API keys, authorization, cookies, secrets, passwords, private keys, objetivos, prompts, respostas, inputs/outputs e argumentos de ferramentas. A captura de conteúdo continua rejeitada pela política estrita.

## Garantias do middleware

O middleware não usa URI bruta como atributo de span. Ele usa `MatchedPath` quando disponível, que representa a rota normalizada, e recorre a `<unmatched>` em caso contrário. O corpo da request, query string, tokens, objetivos e conteúdo de negócio não são registrados.

O `traceparent` é tratado exclusivamente como contexto técnico. Ele não participa de autenticação, autorização, escolha de tenant, concessão de capability, quota, rate limit ou modo live. Headers inválidos são ignorados com geração/preservação independente do request ID.

O request ID recebido pelo cliente é limitado a 128 caracteres e a um conjunto ASCII restrito. Isso evita injeção de quebras de linha, controle de formato ou dados arbitrários em headers/logs. O ID efetivo é retornado tanto em sucesso quanto em erros HTTP.
