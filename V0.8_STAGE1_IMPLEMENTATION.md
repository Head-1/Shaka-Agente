# Shaka v0.8.0 — Etapa 1: contratos do Plan Engine

## Estado

A branch local `roadmap/v0.8.0` foi criada e está ativa. A Etapa 1 foi implementada no `shaka-core`; a integração com fila, worker, persistência de planos, API e CLI permanece reservada às etapas seguintes.

A cópia local do sandbox não possui remote Git configurado e ainda tinha as alterações locais das Etapas A–C da v0.7.0 staged. A nova branch foi criada preservando o índice e o working tree, sem descartar alterações. No repositório remoto, a v0.7.0 já havia sido mesclada na `main` pelo commit `f35671b`; o clone do usuário deve ser a base para a publicação futura desta branch.

## Contratos implementados

O núcleo recebeu `PlanId`, `PlanStepId`, `PlanSpecInput`, `PlanSpec`, `PlanStep`, `PlanMode`, `PlanRisk`, `PlanApprovalRequirement`, `PlanState`, `PlanStepState`, `PlanTaskState`, `PlanCondition`, `PlanAction`, `PlanApprovalDecision` e `PlanApproval`.

As ações são tipadas e allowlisted para leitura, mutação, execução de ferramenta e efeito externo. Os riscos são monotônicos e determinam um nível mínimo de aprovação. O modo `dry_run` é o default; risco irreversível é bloqueado por default e não existe autoridade implícita do modelo.

As condições são uma enumeração fechada, sem expressões arbitrárias. A estrutura valida IDs, tamanho limitado, dependências existentes, ausência de auto-dependência, referências de compensação, ciclos no DAG, orçamento executável, risco mínimo da ação, limite de tentativas e requisitos de aprovação.

O digest usa SHA-256 sobre representação canônica, neutraliza estado e timestamp de criação e ordena as etapas por `step_id`. A verificação detecta alterações no conteúdo; a ordem de declaração das etapas não altera o digest lógico.

As aprovações são vinculadas a plano, digest, revisão, tenant, etapa opcional, papel, nível requerido, decisão, expiração e revogação. O proponente não pode aprovar o próprio plano. Uma aprovação com escopo de etapa é validada contra o requisito daquela etapa; uma aprovação global usa o requisito máximo do plano.

Os estados de plano e etapa possuem transições fail-closed. Estados terminais não retornam à execução e o estado `unknown` impede retry cego após crash ou timeout. As ações RBAC `ApprovePlan`, `ResumePlan` e `ResolvePlanUnknown` foram adicionadas ao contrato; operadores permanecem sem autorização para essas operações.

## Limites preservados

Nenhum plano foi conectado à execução real. Não foram habilitados endpoints, comandos de aprovação, banco de planos, live execution, compensação automática, subagentes, aprovação automática ou efeitos irreversíveis. O controle total de subagentes permanece fora do escopo atual e deverá receber governança própria quando for planejado.
